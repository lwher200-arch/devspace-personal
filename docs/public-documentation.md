# 公开文档隐私规范

公开仓库描述工具本身，不展示维护者或使用者实际接入的项目。

## 可以公开

- 当前源码中实际存在的功能、模块职责和数据契约。
- 通用请求流程、权限边界、失败条件和验证方法。
- 虚构示例，例如 `workspace-a`、`~/projects/workspace-a`、
  `https://devspace.example.com`。
- 与真实项目无关的最小测试样例及经过审查的结果摘要。
- 依法需要保留的许可证、版权声明和技术兼容标识。

## 不应公开

- 真实接入项目名称、完整目录树、业务模块或项目内文件内容。
- 个人绝对路径、操作系统用户名、私人邮箱、机器名或网络拓扑。
- 实际部署域名、节点地址、隧道标识或未经授权的服务入口。
- ChatGPT 对话链接、会话标识、原始运行记录或未脱敏截图。
- Owner 凭据、Cookie、API key、私钥、数据库、备份或认证请求头。

示例应从空白数据构造，不能只替换真实截图中的标题后继续发布其余内容。

## 发布前检查

1. 检查最终暂存内容，而不只检查当前编辑的一个文件。
2. 检查文本、图片、链接、示例配置和仓库 About 信息。
3. 确认运行数据、专用部署脚本和备份没有进入提交。
4. 用当前源码核对功能说明，不把计划、模拟结果或局部验证写成全面成功。
5. 核对默认分支和远端提交，保留对未覆盖范围的说明。

忽略规则不是秘密识别系统。已经跟踪的文件不会仅因加入 `.gitignore` 而消失。
扫描未命中只能说明已检查的规则没有发现问题，不是“绝无泄露”的保证。

## 历史与平台信息

修改当前文档或重命名仓库，不会自动删除旧 Git 提交、其他分支、平台派生关系
或旧地址重定向。当前页面清理与历史清理是不同操作，不能混为同一承诺。

如果曾公开真正的凭据，应先撤销或轮换相关凭据，再评估历史修复和平台清理。
历史重写会影响协作和引用，必须另行确认，不在普通文档修改中默默执行。

## 数据流说明

本机执行不等于结果永不离开本机。文件片段、命令输出和任务结果会传给请求的
客户端及其宿主。权限应按所需操作与数据范围授予，不把公开仓库与私有运行
环境的边界当成模型上下文传输的完整保障。
