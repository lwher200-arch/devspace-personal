# 架构与请求流

DevSpace 将“对话中的协调”与“本机执行”分开。客户端负责提出和审查操作，服务端
负责协议、工作区身份、权限边界、执行生命周期及结果交付。

本文只描述本仓库的通用结构，不描述任何实际接入项目或私人部署。

## 部署入口与运行系统

根目录的一键脚本是安装与启动协调者，不是新的任务守护进程。它依次准备依赖、
构建、调用现有本地配置向导、启动自己拥有的服务进程，并检查 IPC 就绪及 HTTP
健康。实际 MCP 与代理任务仍由下文的同一套服务和管理器处理。

部署器的目录锁只串行化同一源码目录的部署；它不能协调所有手动启动的实例。
不要从同一源码目录同时热更新多个配置的服务。旧构建备份也不是配置、依赖和
数据库的完整事务回滚。

## 分层结构

### 协议入口

`src/server.ts` 组合 HTTP、OAuth、MCP 会话和工具注册。认证发现端点用于建立
连接，受保护的 MCP 操作需要有效令牌。MCP 会话是传输上下文，不是项目目录，
也不等于长期代理任务。

`src/tool-surfaces/` 按工具界面组织参数和结果。项目操作与代理桥接在现有
服务内注册，而不是另外开启一个公开的提供方控制端口。

### 工作区层

`WorkspaceRegistry` 将已授权目录表示为工作区，区分实际 checkout 与隔离
worktree。文件、指令和审查操作复用工作区身份。

逻辑路径校验与物理路径校验共同处理目录边界；根目录锚点用于发现恢复前后
目标变化。工作树是协作隔离，不是操作系统安全沙箱。

缓存条目同时拥有工作区对象与其物理根锚点，不再用两套 Map 分别清理。标准持久化
存储具有锚点恢复能力时，缓存最多保留 32 项，按最近使用顺序驱逐；数据库中的工作区
与对话绑定不因此删除。每次命中仍校验允许根和物理目标，恢复时仍使用原持久锚点。

不具备锚点恢复接口的旧适配器和无存储注册表保留实例内行为。恢复缓存会重新建立
技能目录，激活记录不持久化；读取技能附属文件前可能需要重新读取已声明的技能说明。

### 直接执行层

- 项目访问负责清单、搜索、读取、分页与内容哈希。
- 补丁模块负责解析、预检、内容版本校验和文件替换。
- 进程会话模块负责命令执行、输出限制、轮询和终止。
- 审查模块保存 Git 支持的检查点，返回可重新查看的差异。

这些操作不需要启动代理推理。只有明确的代理请求进入委派路径。

### 代理执行层

桥接通过本地客户端连接按需启动的守护进程。守护进程中的任务管理器负责
逻辑任务与权限，运行池管理提供方进程，适配器转换不同提供方的协议。

传输使用本机 IPC。逻辑任务可以持久化，运行进程则可以按空闲策略或失败条件
释放；两者不能混成同一套身份。

### 状态与观测层

SQLite 保存工作区、对话绑定、OAuth 客户端/哈希令牌和逻辑代理任务。根锚点与
`bridge_requests` 交付回执由各存储初始化，执行策略、证据及可选用量复用任务的
`execution_json`，不另建用量数据库。

单次 Owner 审批、MCP 传输会话、原生进程会话和运行池资源属于内存状态，不因使用
SQLite 就自动获得重启恢复能力。Owner 身份 Cookie、操作批准与任务提交收据也不同。
日志和工具结果是观测，不是另一套权威状态；Token 观察值不是完整账单。

## 关键不变量

1. OAuth 接入身份、单次操作同意、工作区边界、提供方沙箱分别校验，不相互代替。
2. 工作区身份与原物理根绑定；缓存驱逐、别名或重新打开不能使旧授权接受新的根目标。
3. `requestKey` 的重试必须保留原输入，不确定交付先查询回执，不自动重新执行。
4. 参数、文件或模型上下文变化使旧审批失效；审批窗口不限制已提交任务的运行时间。
5. 用量可缺失，但不能伪装成零、完整账单或确定的费用节省。
6. 缓存、日志和 UI 显示均不能提升目录或执行权限。

## 生命周期与回收

- 待审批和未消费授权：从首次创建固定计时，默认 30 分钟、可配置 30–120 分钟；重启失效。
- 提交收据：在结果返回后保留配置的观察窗口，不授予第二次执行；更晚通过持久任务恢复。
- Owner 登录：可选择固定 12 小时策略，与上述操作窗口分开，不随刷新令牌滑动延长。
- Shell/原生进程：增量输出可被消费，原生任务结束后的最终读取移除会话；重启不自动恢复。
- Codex 受保护轮次：按现有策略使用独立进程并核对运行证据；其他提供方的空闲策略不同。
- 工作区 LRU：容量驱逐，不是时间授权；缓存移除不取消正在执行的任务。

### 停机失败契约

停止接收新连接后，HTTP 排空与应用清理同时推进，并立即观察两边的失败。
应用清理按原顺序尝试定时器、MCP 会话、进程会话、审批提交、OAuth 限流存储、OAuth 存储、
工作区存储和桥接资源；某一步抛错不会跳过后面的步骤，也不会自动重试该步骤。
审批提交仍先于数据库关闭完成等待。

全部步骤结束且 HTTP 排空结束后，零错误正常返回；一个错误保留原错误对象；
多个错误使用 `AggregateError` 保留各原因。`close()` 的重复调用复用同一个 Promise，
包括失败结果，不重复关闭数据库或重放任务。尝试过回收不等于失败资源已经成功释放。

这一契约处理已返回或抛错的步骤，不强制中断永不结束的清理，也没有新增全局停机期限。
强制中断策略和跨重启恢复仍需单独处理。

### 启动失败契约

`createServer()` 保持同步构造接口，不自行监听。构造失败时，按逆序回收已取得的
数据库、桥接和定时器；尚未返回的数据库连接由 `openDatabase()` 自己关闭，
包括工作区辅助表、桥接辅助表或 OAuth 过期记录清理期间发生的异常。
这是资源回滚，不是撤销已提交迁移或删除数据库；现有记录不因绑定端口失败而重置。

CLI 和直接服务入口统一调用 `startServer()`，只有真实 `listening` 事件后才报告就绪。
端口被占用、同步监听参数错误或异步监听错误均先清理已构造的应用，再报告失败；
不自动改端口或终止端口的其他所有者。启动和清理同时失败时保留两个原因。
返回值包含 `httpServer` 和原应用 `close`；完整停止使用
`shutdownHttpServer(httpServer, close)`，单独调用应用 `close` 不停止 HTTP 监听。

OAuth 四个端点继续使用 SDK 默认的独立限流窗口和阈值，DevSpace 显式持有其
`MemoryStore`，在正常关闭和构造失败时调用 `shutdown()` 回收定时器。
复用已经锁定的 `express-rate-limit` 版本，不新建限流算法或关闭限流防护。

## 直接文件操作流程

1. 客户端取得已授权的 `workspaceId` 并读取相关项目说明。
2. 根据范围逐页发现、搜索或读取，检查游标、覆盖状态和排除项。
3. 读取目标文件的当前 SHA-256，生成明确的补丁。
4. 使用 `dryRun` 及完整的 `expectedHashes` 检查准备修改的版本。
5. 执行同一补丁，回读内容，运行相关验证并检查差异。

文件读取会检查类型、编码、大小和读取期间的变化。清单快照不是所有文件内容的
原子快照；必须分别处理目录变化和内容变化。

## 代理任务流程

1. 客户端明确给出任务、工作区、请求键及写入模式。
2. 配置了模型策略时，先预检实际执行入口，并在每轮显式传入模型。
3. 桥接核对目录及当前任务，记录交付回执，再联系守护进程。
4. 管理器校验档案、提供方和权限，创建或续接逻辑任务。
5. 提供方执行器建立会话，执行当前轮次并返回结果。
6. 受保护路径校验对应轮次的运行证据，成功后持久化结果。
7. 客户端取得完成或失败状态，向用户报告证据与实际文件影响。

在网络重试中，同一请求复用同一请求键及输入。交付不确定时先核对记录，不能
把新的请求键当成消除错误的方法。目录串行约束目前属于单桥接实例，不是分布式锁。

## 标识与状态

- `workspaceId`：本机项目操作的工作区身份。
- `agentId`：DevSpace 的逻辑代理任务身份。
- `providerSessionId`：提供方的持久会话身份，不是桌面窗口标识。
- `sessionId`：命令执行的进程会话标识，不等于代理任务。
- `requestKey`：一项任务提交或续接的重试身份，不是认证凭据。
- `reviewRef`：可重新读取的差异审查检查点。

代理存储内部使用 `starting`、`running`、`idle`、`error`、`stopped`。
展示层将它们转换为 `running`、`completed`、`failed`、`stopped`；一轮完成后
仍可在显式请求下续接，不能把 `completed` 理解为永久关闭所有上下文。

桥接交付回执中的 `pending`、`accepted`、`uncertain` 描述的是交付状态，
不是模型工作的完成状态。

## 权限与数据流

授权分为不同边界：OAuth 决定客户端是否可以接入，目录规则约束文件工具，
档案和写入模式约束代理请求，具体执行程序及操作系统账户决定实际运行权限。

目录允许列表不能约束任意 Shell 行为。模型策略不等于操作系统沙箱，受保护
执行的证据核验也不会自动撤销已经发生的文件改动。

工具返回的文本、输出和任务结果会传给客户端及其宿主。公开源码、私有运行状态
与模型所接收的上下文是不同数据集合，必须分别管理。

## 失败与恢复原则

- 不把健康接口成功当作业务操作成功。
- 不把提交回执当作任务完成。
- 不把缺失结果当作安全重试的证明。
- 不在失败后自动更换模型或扩大权限。
- 不把模拟提供方测试当作真实模型执行证据。
- 不在有写入者运行时覆盖数据库或恢复不匹配的状态。

现有实现仍有边界：分页可能重复扫描，文本和运行记录有大小限制，部分错误
仍由文本表示，多实例互斥与状态保留策略也需要继续完善。文档不把这些边界
包装成已完成的功能。

约束变化。验证范围与发布、部署、真实宿主接受是不同阶段，详见 [工程维护](maintenance.md)。
