## 2026-09-08 - Risk profile and fixed Owner login lifetime (L3)

- Current State: Per-operation authorization used the conservative profile; OAuth refresh extended its lifetime on rotation and no reusable Owner browser login existed. Prior uncommitted UI work was preserved.

- Root Cause: Login identity freshness was not represented in token rotation, and the conservative profile also required confirmation for ordinary unguarded file changes.
- Impact: The local deployment now uses high_risk_only and a 43200-second Owner lifetime. Browser identity reuse does not approve operations. Old tokens require one fresh login because their verification time is unknown; client registrations and credentials remain intact.

Local/public health and OAuth discovery returned 200; the live old connection returned UNAUTHORIZED / reauthentication required as expected.
- Compatibility: Defaults retain conservative approval and the old login policy unless explicitly configured. Existing token database format is unchanged. Cutover requires fresh login; rollback requires restoring the previous configuration and build. Credentials, roots, model policy, trusted clients and supervisor settings were preserved.
- Known Risks: This is not complete action-by-action approval inside Codex. Arbitrary shell/process input, sensitive aggregate diffs and unconstrained Codex delegation still require approval because their effects cannot be reliably inferred from a task label. Host confirmations are independent. New real login and Chat UI acceptance require the user; no production credential was entered by the assistant. No commit/push this iteration.
