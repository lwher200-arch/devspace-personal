# 部署与步骤引导

本文只使用虚构目录和示例域名。先部署本地服务，再单独验证远程连接。

## 文档与验证入口

完整资料见 [文档导航](README.md)，当前工具与预算见 [工具目录](tool-reference.md)。
维护源码时运行 `npm run typecheck`、`npm run test:docs`、`npm test` 和
`npm run test:deploy`。一键部署本身不等于执行了所有测试，也不证明远程宿主可用。

## 先准备什么

1. 安装满足 `package.json` 中 `engines` 的 Node.js，包含 npm。当前要求是
   `>=22.19 <27`；安装后重新打开终端。官方入口为 https://nodejs.org/。
2. 安装 Git，官方入口为 https://git-scm.com/。
3. 克隆本仓库，或者下载并完整解压 ZIP。不要在压缩包预览窗口直接运行脚本。
4. 准备一个确实允许访问的已有项目目录，不选择整个磁盘或用户目录。

普通命令通道使用现有平台执行器：Windows 为系统命令处理器，其他平台按
已支持的 Shell 解析。可选提供方可能另外依赖 Bash、账号或模型权限，部署器
不替你安装或授权它们。

需要访问包仓库以获取依赖。部署器使用锁文件和声明的 pnpm 版本，不修改全局
pnpm 或 PATH；没有可用的对应 pnpm 时，会通过 npm 执行固定版本。

## 一次启动整个流程

### Windows

双击根目录的 `deploy.cmd`，也可以在 PowerShell 中执行：

```powershell
.\deploy.cmd
```

缺少 Node 时窗口会给出准备提示。此入口不需要设置 PowerShell 执行策略。

### macOS / Linux

```sh
sh deploy.sh
```

### 通用命令

```sh
npm run deploy:local
```

上述入口都调用同一部署器，不使用另一份机器专用安装配置。

## 五个阶段怎么走

### 1. 检查环境与已有状态

检查 Node 版本、包管理器声明及配置状态。已有配置、凭据或旧格式文件不会
被默认重置。若已有可检查的服务端口被占用，流程会停止，不安装第二份服务
或终止占用进程。

旧格式或只有半套配置时，先检查已有文件与备份，明确修复后再重试。

### 2. 安装依赖并准备构建

第一次会询问：

```text
Install locked dependencies and prepare a local build? [y/N]
```

输入 `y` 后安装锁定依赖，运行类型检查，构建界面与服务端，并核验实际命令
执行器、文件工具 API 和 SQLite 原生模块。候选产物先写入私有 `.runtime`
目录，通过检查后才替换 `dist`，已有 `dist` 会保留为备份。

构建没有通过时不会把候选目录当作成功部署。下载与原生模块安装可能耗时，
以退出码和最后的就绪提示判断结果，不把普通构建警告当作必然失败。

### 3. 引导配置本地访问

首次配置复用 `devspace init --local`：

- **项目目录：** 输入允许访问的已有目录，多个目录用逗号分隔。目录可以包含
  空格；路径本身含逗号时请使用配置文件明确设置。
- **端口：** 输入 1 到 65535 的整数，默认 `7676`。若端口已有用途，选择其他端口。
- **Owner 凭据：** 初始化完成后只在本机终端显示，妥善保存，不截图或公开。
  已显式提供的环境凭据保持其优先级。

新配置绑定 `127.0.0.1`，不要求公网地址，不自动启用代理或桥接写入。
新本地配置的状态与工作树目录位于配置目录下；已有配置的路径和权限不变。

这不等于整个服务只读：普通文件工具可以修改授权目录，命令仍以服务账户权限
执行。只向可信客户端提供 Owner 授权。

已有完整配置时跳过向导并原样复用，不重复生成 Owner 凭据。取消向导不会被
当作配置成功，也不会继续启动服务。

新配置默认启用逐次 Owner 高风险授权；旧配置不自动改变权限模式。操作分类、
确认页面和双模型配置见 [用户授权与双模型路由](authorization.md)。初始化向导
使用配置目录级锁，同一配置的第二个向导会停止，不覆盖第一个向导的凭据。

### 4. 启动自己拥有的服务

启动前再次检查配置与端口。服务通过本机 IPC 返回就绪身份，部署器随后访问
健康接口。其他应用返回一个类似健康页面，不会替代子进程的就绪确认。

### 5. 本地就绪与下一步

成功后显示：

```text
[5/5] Ready: http://127.0.0.1:7676/mcp
```

端口以你的选择为准。终端保持打开，按 `Ctrl+C` 停止本次服务。Windows
终端可能将手动中断显示为非零退出；应同时确认服务已停止和端口已释放。

这是前台部署入口，不是开机服务安装器。它不会创建系统计划任务、自动更新
后台进程或配置公网隧道。

## 常用选项

```sh
# 只读检查：不安装、不初始化、不迁移、不启动
node scripts/deploy.mjs --check

# 只准备依赖与构建，不碰配置或启动服务
node scripts/deploy.mjs --prepare-only --yes

# 完成构建与交互配置后退出
node scripts/deploy.mjs --no-start

# 明确选择另一套私有配置
node scripts/deploy.mjs --config-dir ~/.devspace-demo

# 停止相关服务后，明确重新构建
node scripts/deploy.mjs --rebuild

node scripts/deploy.mjs --help
```

`--yes` 只同意依赖准备，不能代替项目访问授权。首次配置需要交互终端；
自动化准备可用 `--prepare-only --yes`。配置目录可使用环境变量
`DEVSPACE_CONFIG_DIR`，命令参数优先。自定义配置目录应位于仓库外，或明确
被忽略的 `.runtime` 内。

源文件或 Node 版本改变时，已有带标记的构建会被识别为过期，要求显式
`--rebuild`。没有部署标记的旧构建也需要经过准备流程，不静默当作新版本。

`--check` 与启动复用同一构建状态判断。损坏的构建记录显示 `invalid`，停止
相关服务后可以显式 `--rebuild` 修复；重建不重置配置。替换候选产物前会再核验
配置与端口，但这不是针对所有手动进程的系统级锁，仍不可热更新共享运行目录。

## 重复运行与恢复

- 配置和凭据默认原样保留，`--rebuild` 不等于重新初始化。
- 更改项目或端口时可明确使用 `node bin/devspace.js init --local --force`；
  这会更新本地绑定、目录、端口并清除公网 origin，应先停止服务并备份配置。
- 端口冲突时检查占用者，不为了通过部署检查而结束无关进程。
- 同一源码目录的部署锁会在正常退出时释放。异常结束留下锁时，先确认原
  部署进程已停止，再处理锁；不要在运行期间强行移除它。
- 候选构建及旧 `dist` 留在 `.runtime` 中。备份不会自动清理，需要自行审查保留。
- 旧构建备份不回滚依赖安装、配置或数据库。恢复必须使用相匹配的代码、锁文件
  和私有状态备份，不能覆盖仍有写入者的 SQLite 数据库。
- 只检查当前配置的端口，不能替你发现所有其他配置的手动实例。不要从同一
  源码目录同时热更新多个运行服务。

如果从新的源码目录复用旧配置，而新目录还没有可检查配置的构建，部署器会
先停止。可在这个独立新目录中，用一个未使用的私有配置目录执行
`--prepare-only --yes --config-dir <unused-directory>`，只准备构建，不创建配置；
然后再用原配置目录运行。不要在仍被服务使用的源码目录上这样绕过升级检查。

## 接入 ChatGPT 网页

本地就绪后还需要你控制的 HTTPS 入口。代理应转发整个服务，而不只是
`/mcp`，以保证 OAuth 发现和授权路由可达。

```sh
node bin/devspace.js config set publicBaseUrl https://devspace.example.com
```

客户端使用 `https://devspace.example.com/mcp`。修改运行配置后，在确认无活动
任务的情况下停止并重新启动本地服务，再通过客户端的正常授权流程连接。

本地部署器不会创建外网隧道、改 DNS/VPN、防火墙、证书校验、全局模型配置，
也不会替你登录提供方账号。

## 分项验收

1. 本机健康接口返回成功。
2. 真实客户端完成 OAuth 和 MCP 初始化。
3. 在授权工作区读取说明文件，并核对返回内容。
4. 在隔离测试文件上预览补丁、修改并回读哈希。
5. 运行相关测试，核对退出码和差异。
6. 需要代理时，再单独验证实际模型、权限和运行证据。
7. 需要远程访问时，再单独验证 HTTPS、宿主权限和工具元数据。

健康检查不是以上所有步骤的替代品。更多信息见 [故障定位](gotchas.md)、
[配置参考](configuration.md)、[架构](architecture.md) 和 [公开文档隐私规范](public-documentation.md)。
