# 工程维护与演进

## 当前原则

保留一个工作区注册表、一条配置加载链和已有任务管理器。提供方适配留在边界，
权限判断不藏进提示词，日志和缓存不另建权威状态。优先修复可复现的缺陷，避免为了
分层名称而添加 Manager、状态副本或重复执行队列。

## 验证门禁

从源码仓库运行，先检查依赖与 Git 状态，再选择相关测试：

```sh
npm run typecheck
npm run test:docs
npm test
npm run test:deploy
```

浏览器回归需要显式设置 `DEVSPACE_TEST_BROWSER`。验证构建后的卡片时，还需要
`DEVSPACE_UI_BUILD_DIR` 指向该候选的 `dist/ui`。不要把条件跳过计作通过。

浏览器辅助模块统一等待 Chromium 调试端点的完整内容，只对暂时缺失或占用的
端点文件进行有截止时间的读取重试，不重试审批、命令提交或其他业务操作。

`npm run build` 会替换当前目录的 `dist`。正在服务的源码目录应先建立隔离候选，
而不是在活动服务下直接执行清理构建。按受测文件哈希固定候选，再验证编译产物。

静态文档检查覆盖根 Markdown 及 `docs`、`examples`、`skills` 中的本地链接，配置测试解析公开 JSONC
示例。它不检查外部网站、标题锚点、完整 Markdown 语法或所有命令示例，也不替代手工审查。

## 发布与运行版本

发布前检查暂存内容、源码/测试契约、公开示例与隐私边界。共享工作区存在并行任务时，
使用独立快照与显式文件清单；不要把刚出现的未完成模块捎带提交。

分别记录 Git 提交、构建指纹、部署回执与宿主发现结果。发布成功不等于本机已经加载，
HTTP 200 不等于 OAuth、文件修改或模型推理成功。远端 CI 必须查看实际任务结果，
因平台或账号原因未启动的任务不能算测试通过。

部署需确认没有活动任务，保留配置和一致性数据库备份，并验证实际启动的进程、
构建、健康与认证发现。回滚不能通过删除迁移记录或重置凭据来绕过不兼容检查。
源码目录的一键部署器、机器专用 supervisor 和用户隧道不是同一个管理层。

## 已完成的受控结构调整

工作区与物理根锚点合为同一缓存条目，避免双 Map 清理不同步。具有可恢复锚点的
持久化存储使用 32 项 LRU，命中更新最近使用顺序；驱逐只丢弃内存对象，不删除数据库记录。
锚点写入成功后才发布缓存。恢复仍核对原锚点，不因目录被重新指向而接受新目标。

无存储或旧适配器缺少锚点接口时，保留实例内行为，不盲目驱逐无法恢复的身份。
恢复后技能激活状态与服务重启时一样重置，必要时重新读取已声明的 `SKILL.md`。
缓存上限不是整个进程的内存上限，也不限制持久工作区记录数量。

示例档案也属于契约：只读角色通过 `writeMode: read_only` 明确权限上限，而不是
只在提示词中要求不修改文件。Codex 示例使用当前个人路由允许的型号，实际账号可用性
仍需预检；未启用的提供方不会因为存在示例而自动启用。

停机辅助模块统一观察 HTTP 与应用关闭结果。应用资源按依赖顺序尽力回收，
保留单个原错误或聚合多个错误，并复用同一次关闭结果。严格异常模式子进程、
实际服务资源关闭和真实 HTTP 排空均有回归测试；测试失败注入不使用生产服务。
这不是自动重启、无限重试或对清理永久阻塞的保证。

## 后续工作不等于已完成能力

- MCP 请求级/无状态兼容需要独立协议迁移，保留 OAuth、审批身份和会话重连测试。
- 工作区与桥接辅助表目前由各存储初始化；若统一进迁移系统，必须设计已有库升级与回滚。
- Shell/原生进程缺少持久执行账本；不能在服务重启后自动重放未知结果的命令。
- 首次并发切换 SQLite 日志模式、部分初始化失败回收、停机期限和健康但卡死的恢复，仍需要独立生命周期验收；已返回错误的停机步骤不再跳过后续资源。
- 项目分页仍可能重复扫描/读取；优化前先测请求数、逻辑 I/O 和完成范围，不能用缓存绕过哈希保护。
- 个人源码版本与 npm 分发身份尚未完全独立；发布 npm 包前另行确定包名、版本和可信发布配置。
- MCP 服务、提供方客户端和 CLI 的版本标识仍有重复来源；应在 CLI 并行工作稳定后复用一个版本读取入口，不能再新增重复版本常量。
- Token 回执是观察值，不是完整账单；控制器、提供方与子代理的计量不能相互代替。

这些项目按风险分批处理，不通过一次大合并、批量删除旧代码或关闭安全检查来完成。
